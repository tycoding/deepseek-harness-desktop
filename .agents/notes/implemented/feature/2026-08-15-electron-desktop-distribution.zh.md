# Agent Note: 使用 Electron 发布桌面版并同步官方代码

Status: implemented

[English](2026-08-15-electron-desktop-distribution.md) | 中文

## Problem

DeepSeek Harness 是由本机 Node.js 服务支持的 Web 应用。桌面版需要在最终用户没有单独安装 Node.js 的电脑上运行，同时持续接收 `deepseek-ai/deepseek-harness` 的官方开发成果。

桌面版专用代码还需要独立位置，避免日常同步官方代码时，把桌面打包规则混入官方拥有的包。

## Decision

`desktop/` 目录统一保存 Electron 应用和所有桌面打包脚本。Electron 在使用自身内置的 Node.js 运行时启动已经构建的 DeepSeek Harness Web 服务期间显示固定的内置等待页，随后在启用沙箱的窗口中加载只监听本机回环地址的页面，并在软件退出时停止服务。页面跳转只接受内置等待页和当前本机服务来源，外部链接交给系统浏览器打开。安装包包含整理完成的应用运行环境和生产依赖。

桌面仓库使用 `main`；官方仓库通过名为 `upstream` 的远程地址使用 `master`。`desktop/upstream.json` 记录桌面版源码当前对应的官方提交。每次生成安装包都要求桌面分支保持干净，先拉取官方 `master`，应用所记录提交之后的变化，使桌面包版本号与官方根目录保持一致，并提交新的官方位置，再安装依赖和构建。更新发生冲突或官方历史被改写时，脚本会在打包开始前撤销本次更新并停止。

`desktop/protected-paths.json` 列出不接受官方补丁改写的本仓库路径，其中包括整个 `desktop/` 目录、根目录双语首页、本 Agent Note 和桌面发布流程。除此之外的文件继续以官方源码为准。应用图标使用 `website/public/favicon.svg` 中的 DeepSeek 官方资源。

运行环境整理过程使用官方构建和部署方式，补齐部署依赖中遗漏但运行所需的工作区包，把包管理器链接替换为实际文件，并为 Electron 重新构建本机终端支持。生成安装包前，冒烟测试会使用 Electron 内置的 Node.js 启动整理后的服务，并要求真实起始页可以正常访问。

每个操作系统生成自己的原生文件：macOS 生成 DMG，Windows 生成 NSIS 安装程序，Linux 生成 AppImage。本项目不承诺在一台电脑上交叉生成其他系统的安装包。桌面发布流程每天检查官方源码，使用 GitHub 的原生 macOS 和 Windows 环境生成安装包，并只在对应标签不存在时创建不可变的 `v<官方版本号>` 发布版本。

## Alternatives considered

**Tauri。** Tauri 可以减小外壳体积，但现有本机服务仍然需要内置 JavaScript 运行时和原生依赖。这会产生两套运行环境衔接方式，增加各系统打包工作，却没有移除本机服务。

**使用浏览器启动器，并要求用户单独安装 Node.js。** 这种方式打包体积较小，但无法满足安装后的软件在用户电脑没有 Node.js 时直接运行的要求。

**重写本机服务，或把它编译成一个原生可执行文件。** 这种方式会把大量官方代码搬进桌面版专用实现，使后续吸收官方更新的成本变高，也会产生超出打包需求的运行差异。

**导入完整的官方 Git 历史。** 这样可以直接使用普通合并，但也会把全部历史文件复制到桌面仓库，并让仓库传输依赖官方完整历史。记录一个经过确认的官方提交并应用后续变化，可以保持桌面仓库独立，同时保留清楚的代码来源。

**把桌面版改动分散到官方包中。** 这样会让桌面版和官方更新同时修改许多文件。把桌面版内容集中在 `desktop/`，可以让可能出现的合并冲突保持集中且清晰。

## Consequences

- 安装后的软件无需系统安装 Node.js 或 npm；代价是 Electron 和服务运行环境都被装入软件，下载体积会更大。
- 生成安装包的电脑需要 Git、Node.js、pnpm、`desktop/` 下的 npm 依赖和原生构建工具；这些不是最终用户的要求。
- 每次生成安装包都会先接收官方 `master`；如果官方改动产生冲突，打包会停止，不会生成来源不明确的文件。
- 明确的保护路径保证本仓库的桌面规则和文档保持稳定；如果新增位于 `desktop/` 之外的桌面文件，维护者必须把它加入清单。
- 原生依赖和安装包需要按操作系统分别准备，因此发布流程需要为每个支持的系统提供一台构建电脑。
- 官方提交继续使用已经发布的版本号时，只更新 `main`，不会替换发布文件；官方版本号变化后才创建新版本。
- 冒烟测试会检查服务启动和真实起始页；各系统的发布流程仍需负责安装包安装和签名检查。
