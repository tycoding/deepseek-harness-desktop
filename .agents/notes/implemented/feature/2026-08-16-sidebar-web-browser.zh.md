# Agent Note: 固定式网页浏览器

Status: implemented

[English](2026-08-16-sidebar-web-browser.md) | 中文

## 问题

桌面应用已经可以在没有外部 Node.js 环境的情况下运行 Harness 前后端，但用户查看本地 HTML 成果或网页资料时仍需离开应用。客户端需要一个能保留当前会话、同时容纳多个工作页面的浏览界面，并且不能让不受信任的内容访问 Harness 来源或 Electron 能力。

## 决策

**由一个客户端插件同时持有入口、右侧面板和打开操作。** `@deepseek-ai/dsh-client-ui-browser` 在 `conversation.session.header.utilities` 注册只显示图标的操作，在 `shell.utility-panel` 注册限定宽度的面板，并提供打开网址和桌面可读 HTML 路径的客户端服务。两个注册共用一份会话级状态。外壳把面板渲染为最右侧栏，因此它会缩小会话区域而不是覆盖应用内容；打开面板时会关闭与它互斥的会话详情栏。

**页签中的页面只在当前界面生命周期内保持。** 状态只保存普通页签信息和当前选中项，不做持久化。每个非空页签在未选中时仍保持挂载，从而保留普通页面状态。关闭最后一个页签时会创建新的空白页签，使地址和文件操作始终可用。

**远程地址与本地文件使用不同的准入路径。** 地址栏和应用内的链接点击只接受规范化后的 HTTP 和 HTTPS 地址，并拒绝 Harness 应用自身来源。本地 HTML 可以通过文件输入进入；在桌面应用中，也可以通过隔离的预加载连接打开不超过 10 MB 的绝对 HTML 路径。两条路径都会生成生命周期绑定到页签和面板组件的临时地址。替换、关闭或卸载本地页签时都会释放该地址。

**页面内容保持隔离。** iframe 允许脚本、表单和页面弹窗，但不授予同源权限。插件既不启用 Electron webview，也不暴露 Node.js 或 Electron 能力。在面板外打开远程地址时，会交给桌面端既有的外部跳转规则处理。

## 曾考虑的替代方案

**使用 Electron `webview` 标签提供完整浏览器导航。** 不采用：webview 需要扩大 Electron 配置，并为页面内容引入另一套权限更高的生命周期；第一版使用 iframe 隔离已经足够。

**增加 Host 文件接口来提供本地页面及其资源目录。** 不采用：这会扩大面向网络的 Host API 与文件服务权限。打包后的应用改用 Electron 预加载操作校验文件类型和大小，同时不向应用页面或嵌入内容开放 Electron 权限。

**跨应用重启持久保存页签。** 不采用：本地临时地址无法跨界面重启恢复，而恢复远程页面还会在没有明确用户操作时重新发起网络访问。

**把浏览器放入覆盖整个应用的浮层。** 不采用：悬浮面板会遮挡会话，也无法参与应用宽度分配。专用工具栏会让会话保持挂载，为会话留下剩余宽度，并在关闭面板后归还空间。

## 后果

桌面端和网页组合都会获得会话页头工具入口和固定式浏览器，支持多个保持状态的页签、应用内链接路由、远程网址、本地单文件 HTML、刷新和外部打开。入口使用通用的右侧面板图标，使该区域可以继续容纳相关工具，而不会表现成只用于浏览器的操作。桌面连接存在时，生成的 HTML 文件会在内部打开；其他文件仍交给系统打开。部分网站仍可能拒绝 iframe 嵌入，跨域页面内跳转也无法更新地址栏或提供可靠的历史控制。插件 README 负责说明这些可见限制和本地临时地址的生命周期规则。
